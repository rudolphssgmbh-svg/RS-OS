## 1. Purpose

This document defines the RSOS Knowledge Application Library.

Its purpose is to ensure that described knowledge can become applicable, testable and automatable.

Knowledge that cannot be applied, verified or transformed into a usable system artifact remains incomplete.

---

## 2. Core Principle

RSOS knowledge follows this chain:

Information
→ Description
→ Classification
→ Evidence
→ Rule
→ Template
→ Validator
→ Workflow
→ Runtime Application
→ Learning Feedback

Described knowledge must be prepared for automated use.

---

## 3. Knowledge Application Rule

Every accepted knowledge unit must define:

- what it describes
- where it applies
- which evidence supports it
- which rule can be derived
- which process can use it
- which validator can check it
- which workflow can execute it
- which feedback can improve it

Knowledge without application path is not operational knowledge.

---

## 4. Automation Requirement

If knowledge is accepted, RSOS must be able to derive at least one of:

- checklist
- validation rule
- template
- workflow step
- decision rule
- evidence requirement
- release gate condition
- runtime monitoring rule
- learning feedback loop

---

## 5. Library Function

The library acts as the bridge between:

- architecture
- governance
- engineering
- knowledge
- runtime
- operations

It transforms written knowledge into reusable system capability.

---

## 6. Final Decision

Decision:

RSOS knowledge must be structured so that it can become applicable and automatable.

Constraint:

No accepted knowledge unit may remain only descriptive if it affects engineering, governance, runtime or operations.
